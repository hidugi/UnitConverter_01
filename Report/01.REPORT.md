## 1. 개요

본 보고서는 UnitConverter_01 프로젝트 **구현·설계 이전** 단계에서 수행한 **Mom Test (STEP 1)** 결과를 정리한다.

Mom Test의 핵심 규칙:

| 규칙 | 요지 |
|------|------|
| 아이디어 말고 **그들의 삶** | “만들면 좋겠어?” 금지 |
| **과거·구체** | “지난번에 ~했을 때” |
| **듣기** | 솔루션 섞이면 “그건 나중” |

**수집 방식:** README·`UnitConverter.py` 맥락과 **현장 소장 페르소나**를 바탕으로 워크북을 채웠다. MagicSquare_xx와 달리 **대화형 멘토 인터뷰 Q&A**는 생략하고, **과거 사실 중심 증거 3건**을 확정했다.

## 2. Mom Test 워크북

### 2.1 페르소나

**소규모 인테리어·리모델링 업체 현장 소장** (워크북 초안: 김민수, 42)

- 국내 자재는 m/cm, 해외·수입 가구·블라인드 견적은 **feet / yard**가 섞여 들어옴
- 현장 도면·재단은 주로 **feet** 기준
- 환산은 검색·변환표·구두 전달로 처리

### 2.2 인터뷰 답변 (과거 사실)

> **수집 상태: 3건 확정** — 시간·오차·누락 단위 구체. yard 검색 소요·일정 지연 일수는 미수집.

| # | 내용 | Mom Test 적합 |
|---|------|:---:|
| 1 | *“지난달 수입 주방 상판 견적이 **meter**로 왔는데, 현장 도면은 **feet**라서 치수 맞추느라 **반나절** 썼어요.”* | ✅ 과거·시간·본인 행동 |
| 2 | *“팀원이 검색해서 **3.28** 곱했다고 했는데, 제가 **3.28084**로 다시 계산하니 **2cm 차이** 나서 **한 번 더 재단**했어요.”* | ✅ 과거·구체·오차 |
| 3 | *“변환표를 사무실에 붙여뒀는데, **yard** 단위 블라인드 견적은 표에 없어서 **또 따로** 찾아봤어요.”* | ✅ 과거·누락·추가 비용 |
| 4 | *“잘못된 치수로 **도어 박스 설치가 하루 밀린 적**이 있어요. 그때 원인이 단위 환산이었어요.”* | ✅ 일정 지연·원인 |

### 2.3 표면 문제 (금지 — 솔루션 섞인 문장)

인터뷰·워크북에서 **기록만** 하고, **문제 정의로 쓰지 않음**.

| ❌ 표면 문제 | 유형 |
|---|---|
| “미터·피트·야드를 한 번에 변환해 주는 **프로그램**이 있으면 좋겠어요.” | 제품 |
| “**CLI**에 `meter:2.5`만 넣으면 전 단위가 나왔으면 해요.” | 기능·솔루션 |
| “**단위 변환 앱**이 없어서 매번 검색해요.” | 필요 가정 |
| “**OCP·SRP·TDD**로 단위 변환기를 만든다.” | 방법론 = 목표 |

README에 명시된 솔루션 요소 (후속 범위):

- 설정 외부화 (JSON/YAML)
- 동적 단위 등록 (`1 cubit = 0.4572 meter`)
- JSON / CSV / 표 출력 포맷

### 2.4 진짜 문제 (한 문장)

**해외·국내 견적의 길이 단위가 현장에서 쓰는 단위와 다를 때마다, 사람마다 다른 방식으로 환산하다가 오차나 재작업·일정 지연이 실제로 발생한다.**

| 축 | 내용 |
|---|---|
| **불편** | 견적 **meter** vs 도면 **feet** 단위 불일치 |
| **비용** | 치수 맞춤 **반나절** |
| **오차** | **3.28 vs 3.28084** → 2cm → **재단** |
| **누락** | 변환표에 **yard 없음** → 추가 검색 |
| **일정** | 단위 환산 오류로 **도어 박스 설치 하루 지연** |
| **재현** | 팀원마다 **다른 상수·방식** |

## 3. Mom Test 증거 3줄 (확정)

1. *“지난달 수입 주방 상판 견적이 **meter**로 왔는데, 현장 도면은 **feet**라서 치수 맞추느라 **반나절** 썼어요.”*
2. *“팀원이 검색해서 **3.28** 곱했다고 했는데, 제가 **3.28084**로 다시 계산하니 **2cm 차이** 나서 **한 번 더 재단**했어요.”*
3. *“변환표를 사무실에 붙여뒀는데, **yard** 단위 블라인드 견적은 표에 없어서 **또 따로** 찾아봤어요.”*

## 4. 진짜 문제 vs 표면 문제 대비

```
[표면]  "단위 변환 앱·CLI 프로그램을 만든다"
           ↓  (솔루션·기능이 먼저)
[진짜]  "견적·현장 단위가 다를 때 사람마다 다르게 환산 → 오차·재작업·일정 지연"
           ↓  (불편·비용·오차·누락·재현)
[다음]  STEP 2~3 — 세션 3 워크북 · PRD · Rule/Command/Test Loop
```
