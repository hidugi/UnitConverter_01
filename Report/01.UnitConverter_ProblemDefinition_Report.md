## STEP 1 — Observation (관찰)

### 1.1 지금 풀려는 상황

- **소규모 인테리어·리모델링 업체 현장 소장**이 국내·해외 견적과 현장 도면을 동시에 다룬다.
- 견적은 **meter**, 도면·재단은 **feet** 기준이 섞이고, 블라인드 등 일부 자재는 **yard** 단위로 온다.
- 환산은 **검색·변환표·구두 전달**로 이뤄지며, **상수·반올림·누락 단위** 때문에 **재단·일정 지연**이 실제로 발생한 **과거 사실**이 있다.

### 1.2 왜 meter / feet / yard인가

- README·기존 코드가 이 **3단위**를 1차 범위로 둔다.
- 현장 소장 증거에서 **meter↔feet 불일치**(반나절)와 **yard 누락**(변환표에 없음)이 구체적으로 나온다.
- **meter를 허브**로 두면 feet·yard 비율을 **한 계약**으로 고정하기 쉽다.

### 1.3 맥락

- **실무:** 견적 단위 ≠ 현장 단위일 때 **시간·오차** 비용.
- **학습:** Rule·Command·Test Loop(TDD), OCP/SRP는 **후속 리팩터** 축.
- **시스템 비유:** “입력 단위 하나를 **표준(meter)** 으로 정규화한 뒤 **전 단위로 방출**하는 모듈”.

## STEP 3 — 표면 문제 vs 진짜 문제

### 3.1 표면 문제 (잘못된 정의 — 이번에 하지 않음)

| ❌ 표면 문제 | 유형 |
|---|---|
| “**단위 변환 앱·웹 서비스**를 만든다.” | 제품 |
| “**CLI**에 `meter:2.5`만 넣으면 된다.” | 기능·솔루션 선행 |
| “**JSON/YAML 설정·동적 cubit·출력 포맷** 1차 구현.” | 범위 확장 |
| “**OCP·SRP·TDD**를 목표로 한다.” | 방법론 = 목표 |

**오류:** “만든다”만 남기면 **환산 계약·재현·회귀**가 뒤로 밀린다.

### 3.2 진짜 문제 (한 문장)

**해외·국내 견적의 길이 단위가 현장에서 쓰는 단위와 다를 때마다, 사람마다 다른 방식으로 환산하다가 오차나 재작업·일정 지연이 실제로 발생한다.**

| 축 | Mom Test 연결 |
|---|---|
| 불편 | meter vs feet **단위 불일치** |
| 비용 | 치수 맞춤 **반나절** |
| 오차 | **3.28 vs 3.28084** → 2cm·**재단** |
| 누락 | 변환표에 **yard 없음** → 추가 검색 |
| 재현 | 팀원마다 **다른 상수** |

### 3.3 개선된 문제 정의 (정확에 가까운 정의)

**“meter / feet / yard 입력에 대해, 고정 비율로 **전 단위 환산 결과**를 **명시된 계약**으로 **반복 산출**할 수 있어야 하며, 그 환산은 **Test Loop**로 **회귀 보호**되어야 한다.”**

## STEP 4 — 핵심 Invariant

| ID | 불변 | 설명 |
|----|------|------|
| **INV-01** | 기준 단위 | **meter** — feet·yard 간 비율도 meter 경유 |
| **INV-02** | feet 비율 | `1 meter = 3.28084 feet` |
| **INV-03** | yard 비율 | `1 meter = 1.09361 yard` |
| **INV-04** | 입력 형식 | `단위:숫자` (`:` 필수, 숫자 파싱 가능) |
| **INV-05** | 지원 단위 | **meter, feet, yard** (미지 단위 → 실패) |
| **INV-06** | 음수 | **거부** |
| **INV-07** | 출력 완전성 | **meter·feet·yard 셋 모두** 출력 (yard 누락 금지) |
| **INV-08** | 재현 | 동일 Input → 동일 Output (Test Loop로 고정) |

## STEP 5 — 세션 3 워크북

### 5.1 주제 (한 문장)

**견적·도면에 섞여 들어오는 meter / feet / yard 길이를, 누가 환산해도 같은 비율·같은 결과가 나오도록 Rule·Command를 고정하고, Test Loop로 그 환산을 되돌릴 수 없게 만든다.**

### 5.2 R-G-I-O

| | 내용 |
|---|---|
| **Role** | 인테리어·리모델링 **현장 소장** — 단위 불일치 시 **반나절**·팀원 **상수 불일치**·**yard 누락** |
| **Goal** | **길이 환산 기준 고정** — 같은 입력 → 같은 전 단위 결과, 잘못된 입력 **식별** |
| **Input** | `단위:숫자` 문자열 — 예: `meter:2.5` |
| **Output** | meter / feet / yard **전부**로 환산한 일관된 결과 *(앱 UI·파일 저장 아님)* |

### 5.3 성공 기준 (Mom Test 연결)

| ID | 기준 | 증거 |
|----|------|------|
| **SC-1** | 3단위 중 **어느 쪽 입력**이어도 고정 픽스처 **수 초 이내** 전 단위 환산 | 반나절 → **1회 명확 환산** |
| **SC-2** | **3.28084 / 1.09361** 적용, **meter·feet·yard 셋** 출력 | 3.28·재단 + yard 표 누락 |
| **SC-3** | Refactor 후에도 **동일 Input→Output** | 팀원마다 다른 계산 → **재현 계약** |

### 5.4 8계층 — 세션 3에서 만드는 것

| 계층 | 세션 3 | 산출 |
|------|:------:|------|
| **Rule** | ✅ | INV-01~08, 실패 조건 |
| **Command** | ✅ | `convert_length`, `parse_input`(선택) |
| **(Skill)** | △ | Rule↔테스트 1:1, “그건 나중” 범위 유지 |
| **Test Loop** | ✅ | Red → Green → Refactor, `tests/test_convert_length.py` |
| Entity / Config / Formatter / UI | ❌ | 후속 세션 |

## STEP 6 — 훈련하려는 사고

1. **명세 = Rule** — “변환 앱”이 아니라 **비율·단위 집합·입력 형식**을 **문장·테스트**로 고정.
2. **환산 vs 부가 기능 분리** — 이번 세션은 **환산(Command)** 만.
3. **I/O = 계약** — Red/Green이 **의미**를 갖게.
4. **Mom Test → PRD** — 표면 문제(앱·설정·포맷)를 **범위 밖**으로 명시.
